What it matches: [static] dns, $HOME_NET -> any, `dns.query` ending in `.adtrack.example` (dotprefix, endswith, nocase). Minor / High confidence, classtype misc-activity, no MITRE mapping. It shows that a client asked to resolve an ad/tracking domain; it does not show a connection, a download or an infection.
Observations (demo data, week 1 and 2 snapshots):
- Destination is only 10.10.0.53 dns1 (internal resolver, Network team), port 53 - the resolver the sensor sees, not a client. All sources are real clients: 60 workstations in 10.10.100.0/24 (DHCP), 14-24 queries each per week, one pair each, no outlier. 35% in working hours = spread round the clock, like a background app/browser.
- Unchanged week over week: same 840, 60 sources, no new source, no spike.
- Data limit: the snapshot has no queried name, so a second domain under the suffix cannot be told apart.
What the analyst does: nothing for a single workstation (no action item, no containment). It would only matter if one host queried far more than the others, or the domain were also used for something else - neither is in the data. Hypothesis: it is adware/telemetry background noise.
Decision: ASK - it looks empty, but "ad/tracking domains are of no interest" is a policy decision. A blanket route on the resolver is also the shape the playbook warns against (the resolver is shared by all clients), and a source-subnet exception is a broad allowlist, which is not allowed.
Question for Network (dns1 owner) / IT security: "Is DNS resolution of `*.adtrack.example` considered a policy concern (adware, tracking), and is the suffix known to be ad/tracking only - nothing used for C2 or a download redirect? Should we hunt for one host that is an outlier instead of alerting on every query?"
Proposed after "no policy concern, domain is ad-only": LOWER to 3 on SID 9900001 + dest 10.10.0.53 + port 53, plus a separate visible rule for outliers (one host over a threshold) if the owner wants that. Not DISABLE: the signature has value if the domain ever turns out to be abused. Not decided now.
Implementation (proposed, not done): route dst `^10\.10\.0\.53$` + `^53$`; no source conditions. | stays visible: other DNS SIDs, other resolvers/destinations (e.g. a client querying an external resolver directly), other domains.
